# STM32 串口 OTA Bootloader（STM32F103 + HAL + Xmodem + W25Q64）

把 STM32F103C8T6 的 64KB 片内 Flash 分成两块：**B 区引导程序**（Bootloader）和 **A 区应用程序**。上电后，引导程序决定是"直接跳进 A 区干活"，还是"先把新固件搬进来再跳"。

新固件有两条入口：

- **串口直刷**：Xmodem 协议把 `.bin` 从串口直接写进片内 A 区；
- **固件仓库**：先把固件通过 Xmodem 存进外部 W25Q64（最多 9 块），再由引导程序按块搬到片内 A 区。

仓库根目录是引导程序（B 区），`app/` 是 A 区应用程序。

> 本项目是 STM32 学习项目，用于理解"两张镜像的接力"：向量表、MSP、VTOR、Flash 分区、Xmodem、外部 Flash 暂存。

## 功能一览

- 上电 5 秒启动窗口：串口输入 `w` 进入命令行，否则自动跳转 A 区
- 跳转前读 A 区向量表、校验栈顶、切换 MSP、反初始化外设
- 8 项串口命令行菜单
- Xmodem（128 字节数据帧 + CRC16）两条下载路径
- W25Q64 固件仓库：9 块 × 64KB
- M24C02 保存 OTA 标志、各块固件长度、版本号
- USART1 921600 波特率 + DMA + IDLE 空闲中断 + 多缓冲区环形队列
- 链接脚本按分区上锁，镜像越界在**链接期**直接报错

## 硬件与引脚

主控：**STM32F103C8T6**（64KB Flash / 20KB RAM，72MHz）

| 模块 | 型号 | 接口 | 引脚 |
|---|---|---|---|
| USB 转串口 | — | USART1 | PA9 (TX) / PA10 (RX)，921600 8N1 |
| 外部 Flash | W25Q64（8MB） | SPI1 | PA5 (SCK) / PA6 (MISO) / PA7 (MOSI) / PA4 (CS) |
| EEPROM | M24C02（256B） | 软件 I2C | PB6 (SDA) / PB7 (SCL) |
| 微秒延时 | — | TIM2 | PSC=71，计数 1 个数 = 1µs |

## 存储分工

三块存储各司其职：

| 存储 | 位置 / 容量 | 放什么 | 在本项目里的角色 |
|---|---|---|---|
| 片内 Flash | `0x08000000`，64 页 × 1KB = 64KB | 引导程序 + 应用固件 | **升级目标**：新固件最终写到这里 |
| W25Q64 | SPI 外部 Flash，8MB，64KB 一块 | 待升级的固件包 | **固件仓库**：先暂存，再由引导程序搬进片内 |
| M24C02 | 软件 I2C，256B，16B 一页 | OTA 信息块（80B） | **通信信箱**：掉电不丢的升级请求和长度信息 |

### 片内 Flash 分区

| 区域 | 页号 | 地址范围 | 大小 | 用途 |
|---|---|---|---|---|
| B 区 | 0 ~ 19 | `0x08000000` ~ `0x08004FFF` | 20KB | Bootloader |
| A 区 | 20 ~ 63 | `0x08005000` ~ `0x0800FFFF` | 44KB | 应用程序 |

这些数字定义在 `Core/Inc/main.h`：

```c
#define STM32_B_PAGE_NUM   20
#define STM32_A_START_PAGE STM32_B_PAGE_NUM
#define STM32_A_SADDR      (STM32_FLASH_SADDR + STM32_PAGE_SIZE * STM32_A_START_PAGE)  // 0x08005000
#define STM32_A_PAGE_NUM   (STM32_PAGE_NUM - STM32_B_PAGE_NUM)                         // 44
```

两个工程的链接脚本也按这个分区写死了上限：

```ld
/* 引导程序 */
FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 20K

/* A 区应用 */
FLASH (rx) : ORIGIN = 0x08005000, LENGTH = 44K
```

这样镜像一旦长大到侵犯另一块区域，链接阶段就会直接报 `region FLASH overflowed`，而不是留到板子上表现成"串口全哑 / HardFault"。

## 两张镜像的接力

### 上电流程

```
复位
 │
 ├─ HAL_Init / SystemClock_Config / GPIO / DMA / USART1 / TIM2 / SPI1
 │
 ├─ M24C02_ReadOTAInfo()          从 EEPROM 0x00 读 80 字节
 │
 └─ BootLoader_Brance()
      │
      ├─ 5 秒窗口：收到 'w' ──────────→ 打印菜单，等命令
      │
      ├─ OTA_flag == 0xAABB1122 ？ ──→ 置 UPDATA_A_FLAG
      │                                 主循环把 W25Q64 里的固件搬进 A 区
      │                                 清 OTA_flag → 软复位
      │
      └─ 否则 ───────────────────────→ LOAD_A(0x08005000)
```

两个"标志"要分清：

| 标志 | 存在哪 | 类型 | 作用 |
|---|---|---|---|
| `OTA_Info.OTA_flag` | EEPROM | 数值标记，用 `==` 比较 | 掉电不丢：决定下次上电要不要升级 |
| `BootStaFlag` | RAM | 按位标志集，用 `\|=` / `&= ~` | 掉电就丢：只用于本次开机把某个流程跑完 |

### 跳转 App：手工重演一次复位

硬件复位时，内核只做两件事：读 `[0x00000000]` 装 MSP，读 `[0x00000004]` 装 PC。引导程序跳 App 就是把这两步手工做一遍，但**不复位时钟和外设**。

```c
void LOAD_A(uint32_t addr)          // addr = 0x08005000
{
    uint32_t app_sp    = *(uint32_t *)addr;         // 向量表第 0 项：App 的栈顶
    uint32_t app_reset = *(uint32_t *)(addr + 4);   // 向量表第 1 项：Reset_Handler

    if ((app_sp >= STM32_RAM_SADDR) && (app_sp <= STM32_RAM_EADDR))
    {
        MSR_SP(app_sp);              // ① 换上 App 的栈顶（汇编 MSR MSP）
        load_A = (load_a)app_reset;  // ② 装 PC
        BootLoader_Clear();          // ③ 把引导程序用过的外设交还
        load_A();                    // ④ 跳过去，不回来了
    }
    else
    {
        u1_printf("A区栈顶非法: 0x%08X，取消跳转\r\n", app_sp);
    }
}
```

几个容易踩的点：

- **栈顶是"第一个不使用的地址"**。20KB RAM 的范围是 `0x20000000 ~ 0x20004FFF`，栈顶是 `0x20005000`，所以校验上界必须**包含** `0x20005000`。
- **跳转不是复位**。USART1、GPIO 还是引导程序配置的状态，所以跳转前要 `BootLoader_Clear()` 反初始化。
- **A 区必须自己搬向量表**。复位后 `VTOR = 0`，内核去地址 0 找向量表；跳到 `0x08005000` 后，A 区要在 `SystemInit()` 里执行 `SCB->VTOR = 0x08005000`，否则中断会跑进引导程序的旧处理函数。A 区工程通过 `USER_VECT_TAB_ADDRESS` + `VECT_TAB_OFFSET = 0x00005000` 打开这个行为。

同一个 `0x08005000` 在四个地方各出现一次，必须完全一致：

| 在哪 | 写的是什么 | 什么时候起作用 |
|---|---|---|
| 引导程序 `main.h` | `STM32_A_SADDR = 0x08005000` | 跳转时告诉 `LOAD_A` 去哪 |
| A 区 `STM32F103XX_FLASH.ld` | `ORIGIN = 0x08005000` | 链接时决定镜像里所有绝对地址 |
| A 区 `system_stm32f1xx.c` | `VECT_TAB_OFFSET = 0x5000` | 运行时决定向量表在哪 |
| 烧录工具 | 起始地址 `0x08005000`（只有烧 `.bin` 才需要手填） | 内容真正落到哪块 Flash |

## 升级流程

### 路径一：W25Q64 固件仓库（`[5]` → `[6]`）

```
[5] 向外部 Flash 下载程序
    → 输入块号 1~9
    → 擦除该块（64KB）
    → 发 'C' 等 Xmodem
    → 每收满 8 包（1024B）写 4 个 256B 页
    → 收到 EOT：Firelen[块号] = 包数 × 128，写回 EEPROM

[6] 使用外部 Flash 内程序
    → 输入块号 1~9
    → 置 UPDATA_A_FLAG，交给主循环：

       擦除 A 区（第 20 页起，共 44 页）
       循环 len/1024 次：
           W25Q64_Read()     读 1KB → UpDatabuff
           STM32_WriteFlash() 写 1KB → 片内 A 区
       末尾不足 1KB 的零头也单独补写
       OTA_flag = 0，写回 EEPROM
       软复位 → 下次上电直接跳新 App
```

### 路径二：串口直接 IAP（`[2]`）

```
[2] 串口 IAP 下载 A 区程序
    → 擦除 A 区
    → 发 'C' 等 Xmodem
    → 每收满 1KB 直接写进片内 A 区
    → 收到 EOT：补写零头 → 软复位 → 跳新 App
```

> 直刷路径中途掉电会留下半截固件，但引导程序本身没被碰过，重新上电后在 5 秒窗口内输入 `w` 就能再次进入命令行重刷。

## Xmodem 协议

```
上位机                                    STM32
  │                                        │
  │  ◀──────────── 'C'（每 1 秒）───────── │  请求开始，并声明使用 CRC 校验
  │                                        │
  │  ─── SOH PktNo ~PktNo Data[128] CRC16 ─▶
  │                                        │  校验通过 → ACK(0x06)
  │  ◀──────────────────────────────────── │  校验失败 → NAK(0x15)，要求重传
  │                                        │
  │  ─────────────── EOT(0x04) ────────────▶  收尾：补写零头
  │                                            直刷 A 区 → 软复位
  │                                            下载到 W25Q64 → 记长度、回菜单
```

| 项 | 值 |
|---|---|
| 帧长度 | 133 字节 = `SOH(0x01)` + 包号 + `~包号` + 128B 数据 + CRC16 |
| 数据帧首字节 | `0x01`（SOH） |
| CRC16 | 多项式 `0x1021`，初值 `0x0000`，逐位计算 |
| 应答 | `ACK = 0x06`，`NAK = 0x15`，`EOT = 0x04` |
| 每包数据 | 128 字节，8 包拼成 1 个 1KB 的 Flash 页 |
| 串口参数 | 921600，8 数据位，1 停止位，无校验，**无流控** |

实现上**只认 `datalen == 133` 的整帧**，所以发送端必须整块发送（SecureCRT 的 `Transfer → Send Xmodem` 即可），不能逐字节粘贴。

## 串口接收：多缓冲区环形队列

串口是**字节流**，"一包"是接收方自己划出来的。这里用 DMA + IDLE 空闲中断来实现：

```
U1_RxBuff[2048]  大缓冲区，循环复用
   │
   ├─ DMA1_Channel5 每次最多搬 256+1 字节
   │    （+1 是故意留的余量，避免 DMA 自己搬满后停掉，
   │      让"一包结束"统一由 IDLE 中断说了算）
   │
   ▼
URxDataPtr[10]   10 个描述符，排成一圈
   │              每个描述符记录这一包的 start / end
   ▼
主循环             URxDataOUT != URxDataIN 就取一包
                   → BootLoader_Event(数据, 长度)
```

IDLE 中断里做四件事：清中断标志 → 用 `256+1 - DMA剩余计数` 算这包实际多长 → 填好描述符 → 停掉并重启 DMA 收下一包。

## 命令行菜单

启动 5 秒内输入小写 `w` 进入：

| 按键 | 功能 | 行为 |
|---|---|---|
| `1` | 擦除 A 区 | 从第 20 页起擦除 44 页 |
| `2` | 串口 IAP 下载 A 区程序 | 擦 A 区 → Xmodem 直刷（`.bin`） |
| `3` | 设置 OTA 版本号 | 逐字符收集 26 个字符，校验后写 EEPROM；ESC/回车退出 |
| `4` | 查询 OTA 版本号 | 从 EEPROM 读回并打印 |
| `5` | 向外部 Flash 下载程序 | 输入块号 1~9 → 擦块 → Xmodem 下载到 W25Q64 |
| `6` | 使用外部 Flash 内程序 | 输入块号 1~9 → 搬进 A 区 → 软复位 |
| `7` | 重启 | 软复位 |
| `8` | 清除 OTA 标志 | `OTA_flag = 0` 并写回 EEPROM |

进入某个模式后，菜单键会被当前模式"吃掉"，所以版本号模式专门给了 ESC/回车退出。

## OTA 信息与版本号

`OTA_InfoCB` 共 80 字节，存放在 M24C02 从地址 `0x00` 开始的位置：

| EEPROM 地址 | 字段 | 说明 |
|---|---|---|
| `0x00 ~ 0x03` | `OTA_flag` | `0xAABB1122` = 请求升级；其它值 = 正常启动 |
| `0x04 ~ 0x2F` | `Firelen[0..10]` | 各块 W25Q64 里固件的字节长度（实际用下标 1~9） |
| `0x30 ~ 0x4F` | `OTA_version[32]` | 版本号字符串，实际只用前 26 个字符 |

版本号格式固定 26 个字符：

```
VER-x.y.z-YYYY/MM/DD-hh:mm
例：VER-1.0.0-2026/10/15-18:00
```

校验**没有用 `sscanf`**，而是手工逐段解析（先比对 `VER-`，再"读一段数字 → 比一个分隔符"循环 8 次）。因为只要链接进 `sscanf`，就会把整个 scanf 引擎拖进 Flash，约 2~3KB —— 对只有 20KB 分区的引导程序来说太贵了。

### 编译

仓库里有两个独立的 CMake 工程：

| 工程 | 位置 | 链接地址 | 产物 |
|---|---|---|---|
| 引导程序 | 根目录 | `0x08000000` | `build/Debug/OTA.elf` |
| A 区应用 | `app/` | `0x08005000` | `app/build/Debug/OTA.elf` |

用 CLion 分别打开两个目录，各编译一次即可。烧录时链接脚本已经指定了地址，用 ST-Link 直接下载 `.elf` 不需要手填地址。

### 生成 Xmodem 用的 .bin

工程的 CMake 里没有配置 `objcopy` 规则，需要手动生成一次：

```bash
arm-none-eabi-objcopy -O binary app/build/Debug/OTA.elf app.bin
```

> `.bin` 不含地址信息，所以只能用在本项目约定的位置（A 区 / W25Q64 块），不能拿去直接烧到别的地址。

### 用 SecureCRT 升级

1. 串口：**921600**，8N1，Flow control 设为 **None**；
2. 上电后 5 秒内发送小写 `w`，看到菜单；
3. 选 `[5]` → 输入块号（如 `1`）→ 菜单提示等待；
4. `Transfer → Send Xmodem`，选择 `app.bin`；
5. 下载完成后选 `[6]` → 输入同样的块号 → 自动搬进 A 区并复位。

SecureCRT 的两个小坑：

- 粘贴是 **Ctrl+Shift+V**（复制 Ctrl+Shift+C）。Ctrl+V 不是粘贴，而是会往设备发一个 `0x16` 字节，还会占掉启动窗口第一个字节的位置。
- 没开"本地回显"时打字看不见，属正常现象。

## 踩过的坑

### Flash 分区越界——"串口全哑"的真凶

**现象**：烧完 A 区后上电一个字都不出，按复位也没用；后来变成"按 7 没反应"，最后 HardFault。

**真因**：链接脚本当时写的是 `LENGTH = 64K`，链接器以为地方很大。引导程序实际长到 `0x080055FC`（约 21.5KB），越过了 A 区起点 `0x08005000` 约 1.5KB。

**两条杀伤路径**：

1. 烧 A 区要擦 `0x08005000` 起的页 → 顺手把引导程序越界的尾巴擦成 `0xFF` → 引导程序打印时跳到被擦掉的函数 → 取到非法指令 → HardFault；
2. 在命令行按 `[1]` 擦 A 区 → 把自己的尾巴也擦了 → 之后任何打印都 HardFault。

**怎么一眼判断**：CLion 烧录时控制台会打印 `Adding extra erase range, 0x0800XXXX ..`，逗号后第一个地址就是镜像结束位置，必须小于 `0x08005000`。

**三招解决**：

1. 把分区写进链接脚本的 `LENGTH`（20K / 44K），越界在链接期报错；
2. 编译优化从 `-O0` 改成 `-Og`：21.5KB → 15.4KB（`-g` 只进调试段，不占 Flash）；
3. `sscanf` 换手工解析，再省约 2.5KB。

> 结论：把"运行期的怪现象"变成"链接期的明确报错"，才叫工程化。

### 魔法数和 EEPROM 测试数据撞车

早期做 EEPROM 整片写测试时，地址 0 附近正好写进了旧魔法数 `0x03020100`。于是每次上电都误判"要升级" → 打印"OTA更新" → 长度错误 → 重启后继续，形成死循环。后来把魔法数改成了 `0xAABB1122`。

### `delay_us(1000)` 其实只等了 1ms

`delay_us()` 靠 TIM2 的计数器实现，TIM2 是 16 位，最多约 65ms；而且原来写的是 `delay_us(1000)`，本意是 1 秒，实际只等了 1 毫秒，启动窗口形同虚设。改成 `HAL_Delay(1000)` 后才是真正的 5 秒。

### 串口是字节流，"包"是接收方自己划的

IDLE 空闲中断的判定门限约等于一个字符时间：921600 波特率下约 10.9µs。PC 侧 USB 转串口驱动常常逐字节发送，字节之间隔着几百微秒 → 每个字节都被判成"一包结束" → 26 个字符变成 26 个单字节包。

所以：

- 多字符输入不能假设"一包到齐"，版本号就是这样改成逐字节攒的；
- Xmodem 必须让上位机整块发送，所以代码只认 `datalen == 133` 的整帧。

### SecureCRT 输不进去

- 粘贴是 **Ctrl+Shift+V**，不是 Ctrl+V；
- 流控要设 **None**，否则驱动会吞/发 `0x11`、`0x13` 干扰数据流；
- 没开本地回显时打字看不见，不等于设备没收到。

## 已知问题 / 待改进

1. **启动窗口只认 `U1_RxBuff[0]`**：任何先到的杂字节（Ctrl+V 的 `0x16`、上位机自动回车、驱动发的 XON、噪声）都会让 `w` 失效。正确做法是从接收队列 `U1CB` 里找。
2. **Xmodem 要求整帧一次到齐**（`datalen == 133`），发送端的发送节奏必须配合 IDLE 划包。
3. **上电自动 OTA 固定使用 W25Q64 块 0**，而命令行 `[5]` 只允许输入块号 1~9，所以块 0 目前无法通过菜单写入——自动升级路径还缺一个入口。
4. **Xmodem 包头序号没有校验**，只校验了长度、`SOH` 和 CRC16。
5. **没有整包完整性校验**：CRC 只保证单个 128 字节包，搬运完整个固件后没有 MD5/CRC 总校验。
6. **缺少"置 OTA 标志"的菜单项**：想测试"上电自动升级"分支，需要先补一个入口。
7. **A 区示例程序占用了 EEPROM `0x10 ~ 0x2F`** 做页大小测试，与 `Firelen[3..11]` 重叠；正式使用时要么把这套测试代码删掉，要么把测试地址挪到 `0x50` 以后。
8. **EEPROM 页大小需要按实际芯片确认**：代码按 16 字节/页写入（本项目的 M24C02、以及 AT24C04 都是 16 字节/页）。如果实际焊的是 8 字节/页的老型号（如 AT24C02），一次写 16 字节会在页内回绕，OTA 信息块会写坏——`app/` 里那段页大小测试就是用来确认这件事的。
9. **还没有上位机软件**，目前靠 SecureCRT 手工操作；可以写一个 Python/Qt 上位机，把"选块 → Xmodem 发送 → 校验"串起来。
10. 两个工程的 CMake 工程名都叫 `OTA`，产物都是 `build/Debug/OTA.elf`，注意别拿错目录。
